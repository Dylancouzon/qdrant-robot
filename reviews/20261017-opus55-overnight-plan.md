# Claude Code Adversarial Review

Target: working tree diff
Verdict: needs-attention

Do not run this plan yet. Its dialogue sessions cannot reach personal retrieval, mechanism 1 fixes no failure anyone observed, and the selection gates almost certainly reject any real gain as noise.

Findings:
- [critical] Five-turn sessions never need statement retrieval (research/overnight-conversation.md:29-33)
  The live window holds four exchanges (robot/main.py:86, HISTORY_TURNS = 4). When turn five is answered, turns one to four are still in the prompt. eval/replay.py:138-147 starts every session with an empty temporary memory. Each conversation gets a fresh uuid4 guest ID (robot/things.py:168-171), and a restart creates a new guest. So in steps 1, 5, and 6, every statement that told() can return is already in the live window. The "isolated store seeds" in step 5 do not exist in replay.py. Seeding would also need a pinned visitor ID, which means growing the harness. The two personal-memory dev sessions therefore measure the live window, not Qdrant retrieval. The validation set has the same problem: in a six-turn session, only turn six can depend on a turn-one fact.
  Recommendation: Make each personal-memory session at least seven turns long. State the fact in turn one or two, add at least four unrelated turns, then ask for it, all inside one guest conversation under 60 s gaps. This needs no harness change. Remove "isolated store seeds" from step 5. Measure enrolled carryover and restart only in the step-4 deterministic checks.
- [high] The two mechanisms miss the failures on record (research/overnight-conversation.md:34-35)
  research/conversation.md:25, 37, and 57 record four observed failures. Scene changes leave questions without replies in history. The Qdrant answer failed even though its source was supplied. A false memory survived deletion. The about_past cue matches the wrong turns. Mechanism 1 removes duplicate statements from the live window, and no record says duplicates caused a failure. Given finding 1, mechanism 1 would remove every statement recalled in dev while the same facts stay in history, so the judged result cannot change. Mechanism 2 picks cutoffs from the labelled scores of the same 24 queries it is then scored on, so it fits to those queries. The robot/memory.py:47 comment shows the two score ranges meet at about 0.53, so a cutoff fitted to 12 positive queries will not generalize. Meanwhile the history repair, which has a traced failure, runs only if a mechanism is parked (step 7).
  Recommendation: Run step 7's history-assembly repair as mechanism 1, because conversation.md:57 already traces that failure. Run mechanism 2 second: fix the candidate cutoffs ahead of time from the existing robot/memory.py:47 score ranges, or split the 24 queries into a selection half and a check half. Run duplicate removal only if the step-5 prompts show duplicates pushing out useful evidence.
- [high] Selection gates will reject any real gain as noise (research/overnight-conversation.md:42)
  The plan requires at least four extra passes out of 40 in each paired repeat. Either mechanism changes at most the roughly 10 personal-memory turns, and only a few of those depend on recall. The drift check fires when more than two of 40 outcomes differ, but the same code has already swung three of 18 (7/18 to 4/18). That check will likely end ranking at step 5. Validation must lose no passing turn in any capability, which means about six turns per capability on 24 turns, so one random flip rejects the finalist. Visual-claim failures must be zero in absolute terms, but the baseline may already fail that check. The result would be a costly night that rejects by default.
  Recommendation: Score each mechanism on the turns it targets, such as recall-dependent turns and retrieval precision and recall. On all other turns, allow no regression beyond the variance measured between the two baseline runs. Use the deterministic checks for the zero-tolerance privacy and deletion gates. Allow no more visual-claim failures than the baseline. On validation, allow a net loss of at most one turn per capability.
- [medium] Replay budget does not add up (research/overnight-conversation.md:44)
  Count the full replays in steps 5 to 8. The baseline needs two runs plus one diagnostic repeat (3). Mechanism 1 needs one run plus one revision (2). Mechanism 2 needs two cutoff runs plus one revision (3). The combined candidate needs one (1). The conditional history repair needs one run plus one revision (2). The final paired repeat needs two (2). That totals 13 to 14 runs against a cap of 12. The plan also gives no wall-clock time per 40-turn replay on the Jetson, even though Jetson access starts only after another session releases it. Threshold cutoffs need no LLM replay at all, because step 4 can score them.
  Recommendation: Screen the cutoffs on the Mac with the step-4 retrieval set (E), then send at most one cutoff to a full replay. Write an explicit allocation of the 12 runs, and take a minutes-per-replay figure from the 2026-10-15 regression results. Define a Mac-only end state for the case where the Jetson never becomes free.
- [medium] Validation sealing has no enforcement (research/overnight-conversation.md:30)
  The plan seals validation from the implementer. However, the only extra authors allowed are Sonnet readers who must not edit, and someone has to write the fixture files. Opus coordinates the judge, so validation questions and rubrics will pass through prompts and the judge cache it reads. Object discussion needs fixture frames, and the dev conversations reuse two images (m2-laptop, m2-pepsi), so validation may share visuals with dev. Irrelevant-memory rejection in a six-turn guest session also runs into finding 1.
  Recommendation: Let the validation author write only to one new fixture file plus a committed hash. Run the validation with one command, and read only the per-capability counts until the keep-or-reject decision is in DECISIONS.md. Require frames that no dev session uses. Place the irrelevant-memory distractor more than four exchanges back.
