## Alternatives and proposed choice

A extends the existing `seen` shard with named 384-dimensional `observed` and `dialogue` vectors. Each source point remains authoritative. Short units become a small MaxSim multivector on that source point, rather than child points. Hydration constructs separate observation and utterance events from the same source. Existing deletion, frame ownership, retention, people links, and named-object links keep their source IDs. Native schema additions preserve old slots and allow the old release to load the shard. Measure schema compatibility, indexed units, lookup quality, query latency, and deletion behavior.

B creates a separate 384-dimensional event shard, with one point per short unit and explicit source links. It gives each unit its own scope and timestamp. It also adds joins, source-deletion propagation, orphan cleanup, retention, and another shard lifecycle. Measure the same quality and resources, plus those write and recovery costs. Use B if native multivectors cannot meet the query or update budget, or per-source fields cannot preserve scope.

Prefer A provisionally. Edge 0.8 exposes `create_dense_vector`; a temporary Mac shard added a dense slot, updated it, flushed, closed, reloaded, and queried both slots with unchanged IDs. Repeated creation with the same specification succeeds (E). This disproves a forced full-migration assumption. A second temporary shard adds MaxSim units, persists them, and deletes them with the source. Repeated creation before and after reload preserves both old and new queries (E). Jetson performance remains unqualified. Official skills warn that large multivectors are costly; these units must stay few, with measured query cost. No new embedding model, sparse retriever, fusion weights, or independent shard is justified yet.

Direct short source units are the first retrieval design. Source-linked generated summaries are an alternative only after direct retrieval leaves a measured reference gap. Summaries add another derived record and can turn guesses into facts. They do not belong in this implementation.

## Record contract

An event identity is the pair of source point ID and kind. Derive it during hydration; persist no second event copy. Its `source_ids` contain the authoritative source point. Its kind is `utterance` or `observation`; detector sightings keep their existing path. It includes capture time, utterance start/end when applicable, object/track references when known, scope, expiry, full source text, indexed short units, source text hash, and uncertainty. Source point IDs remain separate from fixture source IDs. A frame capture timestamp cannot stand in for when a visitor spoke. Legacy utterance times remain unknown; omit legacy sources from neighbor expansion when chronology cannot be established.

The source point retains the JPEG path, capture timestamp, and complete actual ASR text. An observation description remains a model-derived description linked to that JPEG. It never becomes an independent observed fact. The robot's generated reply is excluded from searchable observed/told facts. Questions and requests can be indexed as literal utterances, without treating their propositions as true. Hydration returns the literal source type and provenance.

Use BGE-small-en-v1.5, 384 dimensions, current preprocessing, and 128-token input limit. Split source text at tokenizer boundaries into units that each fit the limit, including special tokens. Preserve the complete source text and unit spans. Do not silently discard overflow. Store one vector per unit in the relevant named slot. Report unusually large sources instead of adding an unmeasured cap or truncating their authority. A single query vector uses MaxSim to select relevant source points; source hydration retains complete text. Qualify this directly with the installed API.

Observation scope permits scene recall without ownership or identity attribution. First-person utterances keep D60/D68/D70 restrictions: the current visitor boundary remains `Robot.since`, with the existing face-continuity or 20 s no-face window. Such utterances from before restart are ineligible. General statements remain shared. Do not create a new persistent identity from a name, fictional speaker, or track ID. Missing legacy scope metadata must fall back to the existing conservative first-person rule.

Expiry and hard caps follow D51: 12 hours, 20,000 source points, and 4 GiB frame files. Current active tracks remain protected. Record capture and utterance times distinctly, and define eligibility before indexing. No derived record extends source retention. Named-vector updates target existing points only. Every delayed write rechecks source existence. Deleting the source point deletes its vectors and payload; frame cleanup remains central in `Memory.forget`. Use independent observation and utterance text hashes, indexed-unit fields, and eligibility checks. Shared observation hydration returns caption/frame fields only; it must exclude restricted utterance text from the same point. Restrict a mixed first-person/general utterance as a whole source. Apply the same visitor checks to every neighboring utterance. Deleted, expired, missing, changed, or unscoped sources cannot be hydrated into evidence. Reuse the existing serialized memory-write worker. Check source text hashes before delayed vector writes and again during hydration. A legacy rollback write that changes text without updating a semantic hash makes that slot ineligible until rebuilt.
